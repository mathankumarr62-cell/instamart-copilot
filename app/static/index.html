Architecture

Four parts run in order. Each writes its graded files and a JSON report to outputs/reports/; this dashboard only reads those reports and files.

  • Part A audits and cleans the raw CSV exports, stores them in SQLite (data/instamart.db) and answers seven SQL questions.
  • Part B builds RFM features, K-means segments and a lapse-prediction model (outputs/lapse_model.joblib).
  • Part C triages tickets through guardrails, redaction, a retried model call, rule-based validation and routing.
  • Part D answers policy questions with TF-IDF retrieval and runs a ReAct refund agent with checkpoints.

Every language-model call goes through the offline mock_llm.py: no network, no API key. The server uses only the Python standard library and binds to 127.0.0.1.

Reproduce the graded pipeline

  1. python -m venv .venv and activate it
  2. python -m pip install -r requirements.txt
  3. python generate_data.py
  4. python run_all.py
  5. python validate.py (ends with ALL CHECKPOINTS PASSED)

Then start this dashboard with python app/server.py. Live demos write only to state/demo/, never to the graded ledger or run log.

Limitations

  • The data is synthetic, so patterns reflect the generator, not real customers.
  • The language model is a deterministic keyword mock; accuracy here says the prompt carries the right signal for the mock, not for a real model.
  • TF-IDF matches exact words only: synonyms such as "money back" for "refund" can miss.
  • The Premium flag is a post-hoc whole-window label, so the retention list is illustrative, not a leakage-free evaluation.
